# 架构改进候选：提升模块深度与可测试性

> 本次审查未发现 `CONTEXT.md` 或 `docs/adr/`，因此未受既有领域词汇或架构决策约束。

## 1. TUI turn-presentation 模块

**涉及文件**：`code-rs/tui/src/chatwidget.rs`（尤其是 `handle_code_event`）、
`code-rs/tui/src/chatwidget/streaming.rs`、`code-rs/tui/src/chatwidget/tools.rs`、
`code-rs/tui/src/history_cell/`。

**问题**：`ChatWidget` 同时协调协议事件、严格排序、流状态、历史插入、spinner、审批、
Auto Drive 与 replay。`EventMsg` 分支跨度约 2,300 行，使一个事件会产生哪些可见后果难以
发现，也难以在不构造完整终端的情况下测试。

**改进方向**：深化一个 turn-presentation 模块，使其拥有“协议事件 → TUI 状态与历史投影”的
转换；`ChatWidget` 保留终端输入和渲染职责。

**收益**：

- Interface 成为事件序列与排序不变量的测试 surface。
- 一个事件 fixture 即可验证 history、stream 和 activity 的结果，无需初始化完整终端，带来
  更高 leverage。
- 该模块通过 deletion test：若删除它，排序和投影规则会重新分散到大量事件分支，说明它能提供
  有效 locality。

## 2. App Server Conversation bridge 模块

**涉及文件**：`code-rs/app-server/src/code_message_processor.rs`，重点包括 conversation
dispatch、listener 生命周期，以及 bespoke event handling。

**问题**：同一模块同时负责无关的 auth/config RPC，也负责 conversation 请求映射、订阅所有权、
core event、审批回调和 wire conversion。`SendUserMessage` 与兼容用的 `SendUserTurn` 还重复了
相同的输入映射和提交逻辑。

**改进方向**：深化 Conversation bridge 模块，集中 conversation 创建、turn 提交、订阅以及
approval/user-input 请求转发；将账户和保存配置相关的 RPC 留在外层。

**收益**：

- conversation 所有权、取消与 wire mapping 获得 locality。
- 测试可经由一个 lifecycle interface 覆盖完整路径，而非跨多个 spawned task 断言实现细节。
- 该模块通过 deletion test：删除后协调规则会重现于每个 conversation RPC handler。

## 3. Invocation-configuration 模块

**涉及文件**：`code-rs/core/src/config.rs`、
`code-rs/app-server/src/code_message_processor.rs`，以及构造 `ConfigOverrides` 的 CLI、TUI、
MCP server 调用点。

**问题**：`ConfigOverrides` 暴露 22 个 optional 字段。每个 invocation adapter 都必须知道哪种
组合有效，而 config precedence 与最终解析发生在别处；其 Interface 的复杂度接近实现复杂度，
属于 shallow module。

**改进方向**：深化 invocation configuration handling：各真实 adapter（CLI、app server、TUI、
MCP）声明自己的 launch intent，由配置解析模块拥有到 effective configuration 的转换。

**收益**：

- 调用者声明意图而非配置机械细节，获得更高 leverage。
- precedence、兼容性与默认值集中，提升 locality。
- 可测试“adapter intent → effective config”，避免复制完整 optional-field 矩阵。
- 已有多个 adapter，故这是 real seam，而非仅为抽象而抽象。

## 4. TUI Auto Drive runtime 模块

**涉及文件**：`code-rs/tui/src/chatwidget.rs`、
`code-rs/tui/src/chatwidget/auto_drive_cards.rs`、
`code-rs/tui/src/bottom_pane/auto_coordinator_view.rs`。

**问题**：Auto Drive 状态变化分散于 coordinator callback、键盘处理、core event、bottom-pane
view model、transcript export、card 更新与 Esc 行为。当前 Interface 将时间与状态转换知识泄漏到
`ChatWidget`。

**改进方向**：深化一个 TUI Auto Drive runtime 模块，使其拥有 lifecycle 与 presentation decision；
widget 仅向其发送用户 intent 和 coordinator/core event。

**收益**：

- pause、stop、review 和 countdown 行为获得 locality。
- 可用确定性的事件序列测试替代大量 terminal 驱动 setup。
- deletion test 表明它具有深度：删除后 lifecycle 规则会重新散布到 input、event 与 rendering 路径。
